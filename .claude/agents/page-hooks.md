the tool is current, this file is not.

## Your page

- NavKey: `hooks`
- Label: Hooks
- Faces: Home
- Entry: `src/renderer/components/tabs/Hooks.tsx`

Reads:
- `~/.claude/settings.json` (User scope, `hooks` key)
- `<cwd>/.claude/settings.json` (Project scope)
- `<cwd>/.claude/settings.local.json` (Local scope)

All three come from `SETTINGS_SCOPES` in `src/renderer/lib/scopes.ts`, loaded and watched via

Writes:
- The same three settings files, only the `hooks` key, saved through the shared config store
  (`src/renderer/state/config.ts`) and `SaveBar`.
- No file on a test-fire: `app:test-fire-hook` spawns the command and returns its output.

## Page invariants

- Hooks live in the `hooks` key of Claude Code's settings files, with Claude Code's documented event names.
  There is no separate hooks store. Source: `SETTINGS_SCOPES` in `src/renderer/lib/scopes.ts`.
- Scope files are watched and re-read on external change through `useScopedConfigFiles` in
  `src/renderer/lib/useScopedConfigFiles.ts`; the page never keeps its own copy as truth.
- Event names and their tooltip docs mirror code.claude.com/docs/en/hooks. The mirrors are `HOOK_EVENTS` in the
  entry and `HOOK_EVENT_DOCS` in `src/renderer/data/hookEventDocs.ts`; they change in the same commit as the docs
  they cite, and events not in the list surface as an "unknown events" warning rather than being dropped.
- Test-fire goes only through the `app:test-fire-hook` handler in `src/main/index.cjs`, validated by
  `appTestFireHook` in `src/main/ipcSchemas.cjs`. It is one of two places allowed `shell: true`
  (`src/main/watchers.cjs` is the other; root `CLAUDE.md`, Avoid list).
- The page uses the list+detail shape of `src/renderer/components/ui/ListDetail.tsx`, as `Skills.tsx` does.
- Saves validate against `settingsSchema` (`src/renderer/lib/settingsSchema.ts`, generated by
  `npm run sync:settings-schema`); never hand-edit the generated schema.

## Boundaries

You own only the files `node scripts/page-surface.cjs hooks` reports as owned. A problem in a shared file or
another page's file becomes a finding naming the owner page; you never fix it. In implement mode, edit only what
the PRD's Files section lists.
