# Code map — load-bearing files + renderer data flow

> Extracted from `CLAUDE.md` on 2026-08-24 (verbatim). Orientation for "which file owns this?".
> Read the relevant entry before editing a subsystem; each records why it is shaped the way it is.

## Architecture (load-bearing files)

**Main process** (`src/main/*.cjs`):
- `index.cjs` — BrowserWindow + IPC registration. Navigation locked: `setWindowOpenHandler` denies, `will-navigate` allows only the dev URL.
- `config.cjs` — fs layer. **All paths go through `validatePath` (allowedRoots = home dir)**. Atomic writes via tmp + rename. Chokidar watchers refcounted per absolute path.
- `transcripts.cjs` — tails `~/.claude/projects/<encoded-cwd>/<sessionUuid>.jsonl`, classifies events, ring-buffers per tab, broadcasts `transcript:event:<tabId>`.
- `memoryAggregate.cjs` — Memory Clusters backend (replaced the old Knowledge Graph tab/`kg.cjs`). Reads one project's workspace memories (the `.md` files under `~/.claude/projects/<encodedCwd>/memory/`, the same store `memoryTool.cjs` owns) and, via a single cost-gated `claude -p` pass (only fires on explicit `refresh: true`), organizes them into named semantic clusters with `[[wikilink]]`-derived connections. Cache: `~/.claude/session-manager/memory-clusters/<workspace>.json`. Spawn pattern mirrors the old kg.cjs: stdin closed, model pinned, hard timeout, `SM_KG_INTERNAL=1` so the prompt-logging hook skips it, brace-matching JSON extractor.
- `chatRunner.cjs` — runs a dormant Terminal tab's chat command as a headless `claude -p --output-format stream-json` job that exits when done (first command `--session-id`, later `--resume`). Serialized through a FIFO queue at concurrency 1 (`SM_CHAT_CONCURRENCY`, clamp [1,3]) so bursts can't fan out into a parallel-`claude -p` OOM. Stop-signal protocol `<<<SM_NEEDS_INPUT>>>`+JSON lets a run ask questions.
- `scheduler.cjs` — runs PRDs from each active project's own `<cwd>/session-manager-operations/scheduler/epics/<epic-id>/prds/` (resolved via `lib/prdLocations.cjs`; queue + history shards live per-project in `<cwd>/session-manager-operations/scheduler/state/` via `lib/queueStore.cjs` — only run logs and PRD_AUTHORING.md remain under `~/.claude/session-manager/scheduled-plans/`) as `claude -p` jobs. Modes: `manual` / `on-reset` / `when-available` (default; polls billing usage every 60 s — `POLL_INTERVAL_MS` in `lib/schedulerConfig.cjs`). Auto-pause on rate-limit, auto-resume at next 5h reset. **Boot reconciliation**: on startup, reaps orphaned jobs (PIDs no longer alive) and logs outcome (success/timeout/error); a still-alive orphaned pid is SIGTERM'd and its classification deferred (`partitionBootOrphans`/`applyOrphanOutcome`, `BOOT_ORPHAN_KILL_GRACE_MS`) so its log isn't misread mid-write. **Dead-process reaper**: background process check + PID-alive validation, run-outcome classifier to detect hangs. (The heartbeat's old 5-minute feedback sweep — scanning each active project's `session-manager-operations/feedback/` and auto-queuing a `/process-feedback` PRD — is gone along with that folder and skill. A job parked in `needs_review` now writes `lib/rcaReport.cjs`'s root-cause report into its run dir and surfaces it on the authoring Epic via `notifyNeedsReview`; it never creates work on its own.) Both reduce manual cleanup of stuck PRD jobs.
- `supervisor.cjs` — every 15 min, Opus probe per running job; SIGTERMs descendant bash on stuck poll-loops without killing the agent. Cost-gated by SM_SUPERVISOR_DISABLE.
- **Definition-of-done gate** (`lib/dodDrainHook.cjs`): fires at queue-drain (when `pickNextBatch` returns an empty batch). Re-verifies each completed PRD's AC live (`reverifyBatch`), flags risky surfaces (`flagRiskySurfaces`), writes `runs/<ts>/definition-of-done-<key>.md` (`writeReport`). Idempotent: `batchKey` (excludes dod/meta slugs) + `reportExists` make a re-drain over the same completed set a single fs-stat no-op. Non-blocking: called fire-and-forget from `tickQueue`; errors are logged not thrown. Skipped when `state.paused` (covers rate-limit), `cancelToken.cancelled`, or no completed jobs. Kill-switch: `SM_DOD_DISABLE=1`.
- `scripts/scheduler-watchdog.cjs` + `scripts/scheduler-watchdog.sh` — external check-and-exit watchdog running outside Electron via systemd user timer or cron (every 2–3 min). Its only job (post PRD 685/686): heartbeat-gated liveness check → `maybeRelaunchApp()` if stale-and-dead. Queue-orphan reconciliation lives in `scheduler.cjs` itself (see above); the feedback sweep it used to also host is retired entirely — do not reintroduce either here. Install via `scripts/install-scheduler-watchdog.sh` (idempotent; `SM_WATCHDOG_DRYRUN=1` for preview).
- `pty.cjs` — node-pty per tab, keyed by renderer-generated UUID = claudeSessionId.
- `ipcSchemas.cjs` — zod schemas validate IPC payloads at the main-process boundary.
- `teams.cjs` — enumerates `~/.claude/teams/<name>/config.json`; gates the `TeamsCard` team chip behind `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`.
- `queueOps.cjs` — scheduler PRD queue linter (unbounded-loop + post-AC overrun detection) + archive + retag.
- `pluginInstall.cjs` — hidden-pty plugin install via `claude plugin install <slug>`. Slug regex `/^[a-z0-9\-/]+$/`, 5 min kill ceiling, single in-flight per slug.
- `memoryTool.cjs` — workspace-scoped memories CRUD for the `memory_20250818` tool.
- `lib/localAdminHttp.cjs` — loopback-only, token-authed HTTP admin API (127.0.0.1, OS-assigned port, token in `~/.claude/session-manager/admin-api.json`). Narrow surface: list scheduler jobs + reset one stuck job. Wrapped as MCP tools by `scripts/scheduler-mcp-server.cjs` (registered in this repo's `.mcp.json`) — `scheduler_reset_job`/`scheduler_list_jobs` only work while the Electron app is running, since that's what hosts the admin server.

**Renderer** (`src/renderer/`):
- `state/config.ts` — per-path FileState with dirty tracking. Backed by config.cjs IPC.
- `state/live.ts` — per-tab derived state (todos, plans, agents, usage) fed by transcript events. Subscribed to `transcript:event:<tabId>` from main process.
- `state/voice.ts` — voice store + auto-submit timer + idle-stop timer + drain watchdog.
- `state/scheduleState.ts` — scheduler queue state (jobs, history, filter state, per-project group ordering). Subscribed to schedule IPC events.
- `state/toast.ts` — toast message queue. Consumed by components via `useToast()`.
- `components/tabs/Settings.tsx` — canonical "scoped editor" shape (ScopeSwitcher + SaveBar + JsonEditor). Other scoped tabs follow it.
- `components/tabs/Skills.tsx` — canonical "list+detail" shape. Other list tabs (Hooks, McpServers, Plugins) follow it.
- `components/tabs/Scheduler.tsx` — Scheduler cockpit (Almanac design). Renders Queue/PRDs/History via SchedulePanel + scheduleState.
- `components/tabs/Memory.tsx` / `MemoryNaturalPanel.tsx` — Memory Clusters UI over `memoryAggregate.cjs`'s output. Replaced the old `KnowledgeGraph.tsx` graph-visualization tab (KG feature retired; its prompt-log ingestion pipeline is gone).
- `components/SchedulePanel.tsx` — modular pane (Queue/PRDs/History tabs). Extracted 2026-06 to be reusable across multiple parent tabs. Owns filter state.
- `components/tabs/scheduler/sched-primitives.tsx` — Almanac design shared: SchBadge (status color/mark), ProjectTag, DetailBlock/Line (project dots hashed-color palette).
- `components/ui/` — shared primitives (Panel, ScopeSwitcher, SaveBar, JsonEditor, KVTable, ListDetail, Toggle, EmptyState).
- `components/layout/AlmanacFooter.tsx` — the BOTTOM information bar, and the app's only status strip (connected dot, **session (5h) + weekly (7d) usage pills**, conditional scheduler-paused pill, active tab + branch via `lib/useBranch.ts`, last-activity, todos, app version). Pills navigate to Settings / Home / Scheduler on click; both usage pills route to Home, where `home/UsageMeters.tsx` renders the full meters. The two surfaces read the same `billing.usage.five_hour` / `seven_day` windows and share `lib/usageWindow.ts` (`utilPercent`/`formatReset`/`usageTitle`) so their percentages and reset times can't drift — don't re-derive either locally. The complementary rule holds for the TOP bar (`components/TabBar.tsx`): it is navigation ONLY — the Home pill plus one tab per open project — after its duplicate app-name+version block was removed 2026-08-08 (app identity = native window title + this footer's version chip). Status/usage/branding belong to the footer, never the tab strip. That strip scrolls horizontally when the open projects outrun the width, but its scrollbar is hidden via `.no-scrollbar` (styles.css) and the bar is `h-12`: the app's global `::-webkit-scrollbar` is 10px, which inside a fixed-height bar painted a permanent grey sliver under the tabs that read as a stray widget and ate a tenth of the bar's height. Hidden, not disabled — wheel, drag-reorder, and keyboard still reach an off-screen tab. E2E "app booted" waits key off `[data-testid="tour-tabbar"]`, not the old `text=Claude Session Manager`. (Renamed/redesigned from the pre-Almanac `AppStatusBar.tsx`, which no longer exists — it had no model/effort/team/voice pills; the team chip lives only in `components/ui/TeamsCard.tsx` now.)
- `components/CommandPalette.tsx` — Cmd-K palette with fuzzy filter + emit-only dispatch. Suppressed inside Monaco / text inputs.
- `components/ui/Toast.tsx` — non-fatal error surfacing. `info / warn / error`. Mounted above modals, below RecordingStatus.
- `lib/prdFrontmatter.ts` — round-trip YAML preservation for SchedulerPrdsView.
- `lib/chatVerbosity.ts` + `state/chatPrefs.ts` — the chat-feed **density dial**, rendered as `EpicDetail.tsx`'s `VerbosityDial`. **Five levels, numbered LOUDEST-first for humans** (1 `raw` · 2 `detail` · 3 `standard` · 4 `brief` · 5 `summary`) — the inverse of the module's internal rank, an inversion expressed in exactly one place (`levelNumber`); everything else compares ranks. `turnMinVerbosity(turn)` maps every turn to the quietest level that shows it: interactive roles (`user`/`assistant`/`question`/`notice`/`error`) → `summary`; **tool-family + `tool_result` + `content_thinking` → `detail`, i.e. tool cards appear at levels 1–2 ONLY**; `queue-operation`/`file-history-snapshot` + `edited_text_file`/`queued_command` attachments ("what changed") → `standard`; everything else, **including any unknown/future kind**, → `raw`. Three per-level affordance helpers keep the rules in the lib rather than scattered in JSX: `showsToolStrip` (a *completed* assistant turn's own strip + its diff cards, same 1–2 rule), `showsInjectedPreamble` (level 1 only — see `promptPreamble.ts`), and `ASSISTANT_CLAMP_CHARS` (level 5 only, behind a per-turn "Show full message"). **Two invariants outrank the dial:** a turn asking the human something is never hidden or clamped at any level (hiding a `question`/`notice` strands a run waiting on an answer nobody can see), and the **in-flight** bubble keeps its tool strip at every level (mid-run it's the only progress signal there is). Nothing is dropped from the store, so raising the level restores the byte-exact record with no re-read. Prefs persist to `~/.claude/session-manager/chat-prefs.json` as a global default + sparse per-Epic override, with a one-line forward-migration of the retired 3-level `verbose` value. This is a filter on *reporting*, distinct from `ChatTranscriptTurn.tsx`'s event router, which remains "a router, never a filter".
- `lib/promptPreamble.ts` — the FIRST feature gated on that dial. `chatRunner.cjs` prepends `STOP_SIGNAL_INSTRUCTION + CHAT_MODE_TRUTH_INSTRUCTION` (~1.4k chars) to every prompt, and since the CLI's JSONL records what it was actually sent, the transcript-derived user turn is mostly boilerplate with the human's sentence at the bottom. `splitInjectedPreamble(text)` peels those blocks off for display, and `Turn`'s `injectedPreamble='hidden'` collapses them behind a tiny `≡` glyph (EpicDetail passes `'hidden'` at every level but 1, via `showsInjectedPreamble`). The renderer can't import the main-process `.cjs`, so each block is anchored on its **first and last sentence only** rather than a copied literal — `src/main/__tests__/chat-preamble-anchors.test.cjs` composes the REAL exported constants and fails if a rewording breaks the anchors. The splitter refuses to strip when a block's closing sentence is missing, when stripping would empty the bubble, or when the boilerplate appears anywhere but the very front (a human quoting it). `turn.text` is never rewritten — the raw footer still yields the byte-exact sent prompt; only Quote narrows to the human's own words. **This asymmetry is also the dedupe key in `state/chat.ts`**: `beginRun` pushes an optimistic user turn holding what the human typed while the JSONL holds the preamble-prefixed version of the same message, so `findRecentDuplicateTurn` compares `turnIdentity` (`splitInjectedPreamble(...).body` for `user`, raw text otherwise) — comparing raw text rendered every prompt twice in the Discussion. On a match the feed turn UPGRADES the optimistic one in place (text/`ref`/`kind`/attribution) rather than being dropped, so Show raw and the `≡` disclosure survive; a twin that already has a `ref` is a genuinely repeated line and is discarded.
- `lib/knownProjectAggregate.ts` — **a PROJECT is a CWD**, enforced in one pure place. `~/.claude/projects/` is a store of *transcripts*, not of projects: the CLI mints one folder per encoded path it was ever launched from (throwaway `/tmp` dirs, scratch worktrees, test fixtures), and several folders can resolve back to one working directory. `aggregateProjectsByCwd(rows, enriched)` folds `useKnownProjects`' per-folder `rows` into one `ProjectAggregate` per unique `normalizeCwd(cwd)` — counts/bytes sum, `lastSession` maxes, the newest folder becomes the representative (`encoded` + enrichment `details`), and every contributing folder is kept in `encodedIds` so archive can remove all of them. **A row whose cwd never resolved from transcript content is DROPPED, never guessed**: the old `enriched[encoded]?.cwd ?? candidatePath(encoded)` fallback fabricated a path out of a naive `-`→`/` decode, which is what made Home report *2044 projects* and list rows named `l2mclS`/`SrR7IF`, and made EpicsWorkspace/NewEpicCard hydrate Epics against thousands of directories that don't exist. Every "list the projects" surface consumes `useKnownProjects().projects` (Home's `ProjectsCard` + New-epic drawer via `lib/homeProjectRows.ts`, `EpicsWorkspace`/`NewEpicCard` `knownCwds`, `ProjectsWorkspace`'s launcher — whose pins are keyed by cwd); raw `rows`/`enriched` are folder-level bookkeeping only. **History's analytics carry the same rule** via `lib/historyProjectFold.ts`: `history:dashboard` buckets on `encodedCwd` (`historyAggregator.cjs`), so `foldHistoryDaysByCwd(days, cwdByEncoded)` re-keys every day's `byProject` to the resolved cwd before `facetSlice`/`buildProjectRows`/`BudgetStrip`/the drill see it — merging `toolBreakdown` AND `byModel`, not just the scalar totals. It reported *2028 projects* here, 2009 of them fixture folders contributing 0 tokens but **4,304 phantom sessions** to the `sessions` measure. Unlike Home, a dropped row here would be dropped *money*, so excluded folders are summed into `excluded` and stated on screen (`history-excluded-note`) — never silently discarded. Folding also makes a project key a real cwd, which retired `HistoryDashboard`'s `encodeWorkspace(activeCwd)` round-trip (and with it the literal-`-`-in-a-path matching bug it existed to work around). Enrichment is two-stage for the same reason — resolve every folder's cwd first, then run the 4-read `enrichProject` once per *unique* cwd (~19 here, not ~2000), with `resolving` distinguishing "none yet" from "none, resolved". The transcript tests that seeded those phantom folders (`transcripts-doFlush-array` / `transcripts-paged-reads` / `transcriptsUsageFor`) now delete their `~/.claude/projects` folder in `afterEach` — they only removed their tmp cwd before.
- `lib/terminalSettings.ts` — the terminal theme (`dark`/`light`/`paper`) + font size, and the one place that says what "theme" means here. **It is a single APP-WIDE preference on this machine, not per project / per Epic / per tab**: every xterm surface (`Terminal.tsx`, `epics/EpicTerminalPane`, `InlineConsentTerminal`) reads it at mount and repaints live off the `sm:terminal:settings` window event, so changing it changes all of them at once. Stored in `localStorage['sm.terminal.settings']` — renderer-only, never `~/.claude/`, never a project's `session-manager-operations/`. **Three unrelated things in this app are called "theme"; don't merge them** — this one (xterm colors), `state/editorPrefs.ts`'s `paper`/`dark` (Monaco + the Editor tab's Display popover, incl. the `sm-paper`/`sm-dark` Monaco themes in `CodeEditorPane`), and the app chrome, which has NO theme switch at all (the Almanac palette is fixed in `styles.css`/Tailwind tokens). Edited from exactly one place: Home's `home/TerminalAppearanceCard.tsx`. It used to be a gear popover floating inside the Terminal pane (`TerminalControls.tsx`, deleted 2026-08-09), which framed a machine-wide preference as a property of whichever session was on screen — don't re-add a per-pane copy.
- `lib/prettyModel.ts` — single source of truth for model-name shortening (incl. `[1m]` context-suffix); every pill/chip that shows a model name imports it — don't reintroduce a local copy.

## Renderer data flow

The renderer uses isolated zustand stores (no cross-store subscription). Data flows: **main process → IPC broadcast → store subscription → selector → component hook**.

1. **Main process** publishes events (config changes, transcript events, schedule updates, etc.) as IPC broadcasts: `config:changed`, `transcript:event:<tabId>`, `schedule:snapshot-changed`, etc.
2. **Zustand stores** subscribe to IPC broadcasts and update their state. Each store is independent; components cannot trigger store-to-store updates.
3. **Components** consume stores via hooks (`useConfig()`, `useLiveTab()`, `useScheduleState()`, etc.). For multi-store queries, compose selectors in the component or use memoized helpers.
4. **Panes** (SchedulePanel, History views) own local UI state (filters, collapsed sections) separate from global stores. Panes are stateless containers that accept props for the data they display.
