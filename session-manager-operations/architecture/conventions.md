# Conventions + Avoid — full reference

> Extracted from `CLAUDE.md` on 2026-08-24 (verbatim). Every "Avoid" entry is a real incident,
> not a style preference — the rationale is the point, so it lives here rather than in CLAUDE.md.

## Conventions

- **Tab ID = claudeSessionId** by design. Used for `--session-id` pass-through and JSONL transcript file lookup.
- **No CommonJS in renderer**, no ES modules in main — `type: module` is set but `.cjs` files for main/preload bypass it.
- **Settings.json validation**: monaco `jsonDefaults` + schemastore.org. No hand-rolled zod for user config.
- **Hot data contiguous**: live state per tab is a flat object, not nested per-event.
- **No backwards-compat shims**: this is a single-author project; just rename and refactor.
- **Privacy invariant**: `RecordingStatus` (App-level, top of window) MUST be mounted whenever `isRecording === true`, and must sit on the TOP rung of the z-ladder so nothing can paint over it.
- **One global z-ladder, `lib/zLayers.ts`** — Session Manager is deliberately a one-layer app; the short list of things that float above the page is enumerated in that file and nowhere else. Rungs, low→high: `dialog` (modals/palette/tooltips/dropdowns) → `tour` → `contextMenuScrim`/`contextMenu` → `contextMenuDialog` (a dialog opened FROM a menu) → `toast` → `recording`. Values are **class-name string literals, never interpolated** — Tailwind's JIT scans source text, so a computed `` z-[${n}] `` emits no CSS and the element silently falls back to `auto`. Local in-pane `z-10`/`z-20`/`z-30`/`z-40` (sticky headers, active-tab overlap, terminal corner buttons) are relative to their own stacking context and are deliberately left out. `lib/__tests__/zLayers.test.ts` asserts the ordering invariants AND greps the whole renderer for a raw z-index >40 outside the ladder — the drift it prevents had already broken two documented invariants (the privacy banner was hidden behind Editor dialogs; toasts raised from a context menu or Editor dialog were invisible). dockview's packaged CSS ships `z-index: 999/9999` internally and is pinned back under the ladder by `workbench.css`'s `--dv-overlay-z-index: 45` — check that file before assuming a stray high z-index is ours.
- **No per-OS UI chrome.** `BrowserWindow` is created with the native frame on every platform — no `frame: false`, no `titleBarStyle`, no `vibrancy`, no traffic-light insets — and no layering value branches on `process.platform`. macOS and Linux render the identical DOM stack; the only renderer-side platform check is `VoiceModal`'s ⌘-vs-Ctrl **label** text. Keep it that way: a platform-conditional layout would double the surface every overlay bug has to be verified against.
- **Toast is the user-facing error channel** — don't swallow errors silently; surface via `useToast().show('error', msg)` (or `toast.error(msg)`) so the user sees the failure. Background hydrate paths can stay logger-only.
- **One ops-root resolver — `opsOwnership.opsPath(cwd, ...segments)`** (PRD 1082). Never `path.join(cwd, 'session-manager-operations', ...)` anywhere else in `src/main/`: the resolver normalizes a linked-worktree or ops-internal cwd to the real project root (`activeSessions.projectRootOf`) and refuses an ephemeral one (`ephemeralCwd`), so the worktree-cwd hazard (2026-08-30, 2026-09-01) is caught by construction. `scripts/ops-sweep.cjs` reports any other literal as `OPS_PATH_LITERAL`. Writers that want fail-closed on an ops-internal cwd pass `{ opsInternal: 'refuse' }` (queueStore.projectStateDir does).

### Guard hook reference-by-shim (`guardShims.cjs`)

`delegationReadiness.cjs`'s `install{PrdWrite,DestructiveGit,InlineImplementation}Guard` write a `node <path>` `PreToolUse` hook into an adopting project's `.claude/settings.json`. That path used to be `path.resolve(__dirname, '../../../scripts/hooks/guard-*.cjs')` — THIS app's own copy, by absolute path, per CLAUDE.md's "adopt by REFERENCE, never vendor" law. Run via `npx claude-code-session-manager@latest` (the normal install path), that resolves under `~/.npm/_npx/<hash>/node_modules/claude-code-session-manager/` — a directory scoped to ONE npx resolution. The next `npx ...@latest` (a new release) or an npm cache prune creates/removes a different hash dir, so every previously-installed hook decays into a dead path. A `PreToolUse` command pointing at a missing script exits non-zero WITHOUT exit code 2 — a non-blocking error to the harness — so it silently guards nothing, while `checkPrdWriteGuard`/`checkDestructiveGitGuard`/`checkInlineImplementationGuard` correctly flip the readiness banner back to red. That decay is why "Delegation not ready" reappeared across projects even after a successful install.

Fix: the three installers now write `node ~/.claude/session-manager/hooks/guard-<name>.cjs` — a STABLE shim that never moves across app upgrades. The shim contains no guard logic of its own (still reference, never vendor): it reads a pointer file (`app-root.json`, rewritten on every app boot with the CURRENTLY running app's root) and `require()`s the real `scripts/hooks/guard-<name>.cjs` from there. An app upgrade (a new npx hash dir) just rewrites the pointer on the next boot; every already-installed project hook keeps resolving through the same shim path with no re-install. `check*Guard` accept BOTH the shim path and a direct app-root path as healthy — only the resolved script's existence on disk matters — so an existing direct-path install (this repo's own `.claude/settings.json`, or a pre-shim adopter) is never reported red. Coverage: `guardShims.test.cjs`, `delegationReadiness.test.cjs`.

### Scheduled PRD authoring

Before writing a new PRD for `<cwd>/session-manager-operations/scheduler/epics/<epic-id>/prds/` (mint/join the Epic first via `scripts/mint-epic.cjs` or the `scheduler_create_prd` MCP tool — never the retired flat `scheduler/prds/`), read [`PRD_AUTHORING.md`](../../src/main/templates/PRD_AUTHORING.md). It codifies two real stuck-job incidents: the **fizzpop poll-hang** (106-fizzpop-publish used an `until $(curl ... | jq .uptime)` loop whose condition was unsatisfiable because Render static-content deploys don't restart the API — hung 2h47m until the watchdog SIGKILLed) and the **etch-engine post-AC overrun** (112-etch-engine declared success at 17:44 UTC then launched a `for seed in 100..50000` fixture generator not in the AC — ran 2h44m until user killed it). The guide has 15 numbered sections; §10 is the pre-queue checklist.


## Conventions (extensions for v0.20+)

- **Almanac design** (Scheduler): SchBadge status colors + project-dot palette. Single source of truth in `sched-primitives.tsx`.
- **Renderer state stores** (zustand): separate concerns: `config.ts` (file-backed, dirty-tracked), `live.ts` (per-tab derived from transcripts), `voice.ts` (voice UI), `scheduleState.ts` (queue + history), `toast.ts` (toast messages). Stores do NOT cross-subscribe; use composed selectors in components for multi-store queries.
- **Modular pane pattern**: extracted panes (SchedulePanel: Queue/PRDs/History tabs) are reusable by multiple parent tabs. Panes own local filter state + filtering logic; parents own scope/context state.
- **Design primitive extraction**: when a design system (Almanac) is shared across components, extract `*-primitives.tsx` with explicit exports (SchBadge, ProjectTag, etc.). Import primitives explicitly by name, not as wildcard — prevents cross-system pollution.
- **Every process Session Manager spawns must be named via `src/main/lib/procName.cjs`** (comm alias + `smArgv0`, `claudeBin.cjs` `claudeSpawnTarget` for `claude`) **and stamped with `SM_PROC_ROLE`** — stamped inside `cleanEnv.cjs` (`cleanChildEnv`; `withProcRole` for the raw-env sites `runClaudeP.cjs`/`docEdit.cjs`/`mcpStatus.cjs`/`supervisor.cjs`), never per call site. Incident (user report, Pop!_OS System Monitor): dozens of anonymous `python`/`node`/`claude` processes with no way to tell what they were or which project they served. Renaming cannot reach the MCP servers `claude` itself spawns (`@playwright/mcp`, `mcp-server-fetch`, `workspace-mcp`, our own `scheduler-mcp-server.cjs`) — they inherit our env, so `node scripts/sm-ps.cjs [--json]` attributes them from `/proc/<pid>/environ` (`SM_PROC_ROLE`, `SM_SCHEDULER_JOB_SLUG`, `SM_CHAT_SESSION_ID`, `SM_PROJECT_ROOT`). `SM_PROC_ROLE` is unrelated to `SM_PROC_ROOT` (`procIdentity.cjs` test override).
- **No scheduler status may be a dead end reachable only by a human `scheduler_reset_job`.** Every `JOB_STATUSES` value must either be genuinely final (`completed`/`skipped`) or have an automated selector that can move a parked row out — `quarantined`'s own exit (`autoResolveQuarantine`, this PRD) was the last gap, since `reconcile()`'s adopt path can only fire once a `createdVia` stamp appears, which never happens on its own. `scheduler-no-dead-end-status.test.cjs` iterates the real `JOB_STATUSES` array and fails if a new status ships with no wired automated exit.

### VAD / ORT wasm assets are derived, not hand-vendored

`src/renderer/public/vad/ort-wasm-*` is copied from `node_modules/onnxruntime-web/dist` by `npm run refresh:vad-assets`
(`scripts/refresh-vad-assets.mjs`); `tests/unit/vad-assets-drift.spec.ts` fails on any byte drift. The top-level
`onnxruntime-web` dependency is **kept deliberately**: `@ricky0123/vad-web` does `require("onnxruntime-web/wasm")`, so
Vite bundles that package's JS into the renderer, and the wasm served from `/vad/` must be the same version as that JS
(it was 1.24.3 wasm under 1.26.0 JS before this guard). Whisper (`@huggingface/transformers`) bundles its own nested ORT
separately. After any `onnxruntime-web` bump: run the refresh script and commit the result.

## Avoid

- Launching a `claude -p` process **without acquiring a slot from `lib/sessionSlots.cjs`** first. That pool (default 5, user-adjustable [0,10] from the Home tab, `SM_SESSION_SLOTS` overrides) is the single machine-wide concurrency limit — scheduler jobs *and* chat runs draw from it. The scheduler's own `concurrencyCap` is **retired**: it was the exact per-consumer private cap sessionSlots.cjs was written to replace, and it silently ceilinged the queue at 3 while the Home tab reported 5. Do not reintroduce a private cap in any consumer. OOM protection is the *memory gate* in `tickQueue` (`RESERVED_HOST_MB` 3000 + `MIN_FREE_MB_PER_JOB` 2500), which is machine-aware — not a hardcoded job count; the 2026-06-10 five-parallel OOM is covered there.
- Gating scheduler batches on **`parallelGroup`**. It is a unique-per-PRD number (PRD 832) and a display/priority hint only — never a barrier. `dependsOn` is the sole ordering primitive. `schedulerBatch.cjs` used to fire one `parallelGroup` per tick and hold every higher one; with unique numbers that reduced every batch to exactly **one job** (measured max concurrency 1 across 25 runs against a 5-slot pool), and because numbers are allocated monotonically upward, each newly queued PRD was always held behind the in-flight one. Removed 2026-08-02; regression coverage in `schedulerBatchDepends.test.cjs`.
- Ordering projects **across** projects by their PRD number (`parallelGroup`/NN). Numbers are allocated PER PROJECT (`allocateParallelGroup` → `prdDirForCwd(cwd)`) and only grow, so comparing them across projects compares unrelated sequences: a long-lived project always sorts behind a young one and starves for as long as the young one keeps queueing. 2026-09-01: social-signals-trader (8 pending, lowest NN 3887) got zero starts for 3.5 h while starry-night-ships (lowest NN 158) took every freed slot. `pickNextBatch` now orders by fewest-running → oldest pending enqueue time → cwd and hands slots out round-robin (PRD 1086); `findStarvedProjects` warns + audits `project_starved` when a project is passed over past `STARVATION_ESCALATE_MS` while others dispatch (PRD 1087). The number stays a priority hint WITHIN a project only.
- Adding `shell: true` to `child_process.spawn` calls — only `watchers.cjs` and `app:test-fire-hook` legitimately need it (user-supplied shell strings are part of those features). Anywhere else, pass argv arrays.
- Reading remote URLs in production — `createWindow` hard-fails if `dist/index.html` is missing rather than falling back to `localhost:5173`.
- Re-implementing the tmp+rename atomic-write pattern. Use `config.cjs`'s `writeJson` / `writeTextAtomic`.
- Cross-subscribing between renderer state stores — e.g., don't read `live.ts` from `config.ts` or vice versa. Each store is an island; components compose them via hooks. Complex queries go in components or memoized selectors, not in store initialization.
- Adding pane-specific state to parent tabs — if a SchedulePanel needs filter persistence, keep it in the pane, not the tab. Panes own their UI concerns; tabs own layout + navigation.
- Importing design primitives via wildcard (`import * as SchElements from ...`) — requires explicit named imports to prevent accidental cross-system usage.
- Returning a freshly-built value from a zustand selector — `useStore((s) => s.x ?? [])`, `?? {}`, `.filter(...)`, `.map(...)`, `Object.values(...)` inside the selector. zustand v5 compares snapshots by reference via `useSyncExternalStore`; a new reference per call means infinite re-render → React #185 → **the whole app renders blank**. Select the raw slice (fallback via a module-level stable constant like `EMPTY_JOBS`) and derive after. Three incidents now: TabBar (see its header comment), an earlier e2e blank-app, and the v0.39.0 boot blank-screen (TerminalChat `scheduleJobs`, fixed in `4ab267b`). Guarded by `npm run lint:selectors` (`scripts/check-unstable-selectors.cjs`) — a fast grep-based check for this exact pattern; run it alongside typecheck.
- Declaring a hook **below a top-level early return** in a component — `if (!snap) return null` … then `const x = useMemo(...)` further down. React counts hooks per render, so a component that bails early on one render and falls through on the next runs a different hook count → **React #300 / #310** → the pane dies into its error boundary ("something broke in this panel"). This is the sibling crash class to #185 above and has bitten once: `SchedulePanel`'s `holdBySlug` memo sat below three early returns (`!snap`, the supervisor sub-panel, `FirstRunGuide`), so the whole Scheduler tab crashed the moment its scoped queue drained to zero jobs or the user switched projects. Hoist the hook above **every** early return and guard its body on the nullable value (`snap?.lastTick`) instead. Guarded by `npm run lint:hooks` (`scripts/check-conditional-hooks.cjs`); `npm run lint` runs both checkers.
- Adding a new LeftNav tab for a live/observability feature before checking whether an existing surface (Terminal, Scheduler) already owns that data. Treat each nav destination as an independent "micro-service" — before adding one, check if an existing item already owns the data/job and extend it (a sub-tab) instead of shipping a parallel UI. When two surfaces read the same underlying state, consolidate rather than duplicate. The nav has been pruned once already (2026-06-03: Scheduler/Plans/Background-Agents merged into one Scheduler destination) after growing to ~31 destinations with real overlap.

- Treating a transcript's recorded `cwd` as a project root without normalizing it first. Claude Code rewrites `cwd` on every subsequent transcript row once an agent `cd`s somewhere, and `activeSessions.cjs` reads the **last** such row — so an agent that steps into a PRD folder makes that folder look like a project. Every consumer then joins the ops subpath onto it and a whole second ops root is materialized underneath the first: `<project>/session-manager-operations/scheduler/epics/<id>/prds/session-manager-operations/scheduler/state/queue.json`, holding `{"jobs": []}`. Reported from starry-night-ships 2026-08-30 — 15 stubs there, 5 here, 17 more across four sibling projects, mtimes spanning 8 days. This is the *second* form of the ops-root hazard: the 2026-08-13 guard only required the cwd be absolute and exist, and these are both. `activeSessions.projectRootOf` now truncates at the first `session-manager-operations` segment (normalize, don't drop — the ancestor really is the project), and `queueStore.projectStateDir` fails closed on an ops-internal cwd for every other caller; loops over many cwds log-and-skip via `queuePathOrSkip` so one bad row can't abort every other project's read or write. Coverage: `opsRootAbsoluteCwd.test.cjs` + `opsRootNestedWrite.test.cjs`. Existing litter: `node scripts/cleanup-nested-queue-stubs.cjs <projectCwd> --apply`.
- Treating "dropped out of `git status`" as synonymous with "reverted" in the shared-tree guard (`evaluateSharedTreeGuard`/`checkSharedTreeGuard`, `scheduler.cjs`). 2026-09-12: PRD 1181 added a bare `logs/` pattern to `.gitignore` and committed it (`aff5607`); eleven untracked `session-manager-operations/logs/*` paths instantly stopped appearing in `git status` even though they were untouched on disk, and the guard's old `reverted = dirtyBefore - dirtyAfter - committed` diff had no way to tell that apart from an actual discard — an otherwise-perfect run (exit 0, commit landed) was downgraded to `verdict: 'shared_tree_reverted'` and parked in `needs_review` for a human with nothing to decide. The baseline now carries each path's porcelain status code (`parsePorcelainEntries`/`uncommittedChangesWithStatus`), so the guard can tell "was untracked" apart from "was tracked-and-modified": an untracked path that vanished from status but still exists on disk is `nowIgnored` (does not downgrade the job), while a tracked path leaving the dirty set is still `reverted` regardless of on-disk existence (its content was restored to HEAD, which is exactly the discard the guard exists to catch), and an untracked path that vanished from status *and* no longer exists on disk is still `reverted` too. Coverage: `scheduler-shared-tree-guard.test.cjs`.

## Distribution

> Moved from `CLAUDE.md` on 2026-09-12 to make room for the `project-partition.md` table row.

Published as `claude-code-session-manager` on npm (`npx claude-code-session-manager@latest`).
`bin/cli.cjs` spawns the bundled Electron binary; `postinstall` runs `electron-rebuild` for
`node-pty`. Linux+darwin only.

**Simple mode**: `--simple` boots a chrome-free single-terminal cockpit (`app:launch-mode` IPC →
`SimpleShell.tsx`, `DEFAULT_PRESETS[0]`; no persisted-tab hydration).
