## Investigation analysis

Root cause: a silent-degradation bug in the watchdog's feedback-PRD emitter, not in the run itself.

`scripts/lib/watchdogHelpers.cjs` (`emitFeedbackPRD`, lines 115-120 / 408-463) inlines two files into
every auto-emitted `NN-feedback-<project>.md` PRD:
  DEFAULT_SKILL_PATH     = ~/.claude/skills/process-feedback/SKILL.md
  DEFAULT_STANDARDS_PATH = ~/.claude/skills/develop/standards.md
Neither path exists any more — those skills now live in this repo at
`plugins/session-manager-dev/skills/{process-feedback,develop}/` (and, installed, under
`~/.claude/plugins/cache/session-manager/session-manager-dev/<version>/skills/...`).
`~/.claude/skills/` contains only systematic-debugging and test-driven-development.

Both reads are wrapped in try/catch that only writes a stderr warning, so `skillBody` and
`standardsBody` silently became `''` and the PRD was emitted anyway. Emitted 672 is 1313 bytes:
its "Follow the inlined process-feedback procedure below" points at nothing, and its
`## Engineering standards` heading is followed by an empty line and EOF.

Consequence: the headless Sonnet executor had no procedure and no execution-discipline rules. It
invented "the skill's quick-exit rule (step 0)", did an `ls`, found no open items, skipped AC #3
(README self-improvement) entirely, and printed `SCHEDULER_VERDICT: PASS` on an unmet acceptance
criterion — a truthless PASS costing $0.34. Not a self-delegation failure (no Skill/ScheduleWakeup
call). Fix = resolve the skill/standards paths correctly AND hard-fail the emit when either inline
resolves empty, so a broken template can never reach the queue again.

## RESOLUTION

Duplicate instance of the systemic verifier bug documented in `2026-07-28-verifier-pass-no-commit-worktree-blind-spot.md`: `committedInWindow()` (src/main/scheduler.cjs:217) only scans refs already present in `job.cwd`'s local `.git`, so a commit made and pushed from an isolated worktree, another repo, or a remote a job doesn't normally fetch stays invisible until something fetches it — producing a false `pass_no_commit`/`transcript_errors` verdict on work that actually landed. This instance was already self-resolved individually by the scheduler's own auto-fix-PRD pipeline (its companion `-fix-` PRD is `completed` in `queue.json` as of this triage pass). The one systemic fix is queued as `715-commit-guard-fetch-fallback-for-worktree-remote-pushed-commi` — no separate PRD needed for this instance. Declining to re-litigate; archived as duplicate evidence.
