# `manual/` — source of The Session Manager Field Manual

This folder is the **authoring source** for the free Field Manual published at
[bilko.run/manual](https://bilko.run/manual) — every chapter and both downloads, no purchase. The
built release bundle is committed into the sibling `~/Projects/Bilko/` repo; nothing in this
folder is served directly.

## Ownership

Not an `OWNERS` namespace (`src/main/lib/opsOwnership.cjs`). Like `HUMAN_LEARN/` and `reviews/`,
this is skill-authored documentation written with the `Write` tool, not app-owned runtime state
read back through `config.cjs`. There is no concurrent-write hazard to guard: one skill invocation
authors a release, a human reviews it, `web/manual/build.mjs` emits it. Enumerated in the root
`CLAUDE.md` alongside the other non-`OWNERS` folders.

## Writing style

[`STYLE.md`](STYLE.md) is the single writing contract for the manual's voice, reading level,
chapter template, and component vocabulary. Read it before writing or revising any chapter —
every chapter PRD and every `builder:manual` revision reads it first.

## Shape

```
manual/
├── STYLE.md                  # writing contract — voice, reading level, component vocabulary
├── manual.json               # source manifest — version, chapters, downloadable assets
├── chapters/<slug>.html     # one file per chapter; plain HTML fragments, no <html> wrapper
└── figures/                 # annotated screenshots (copied verbatim into the release)
```

No `assets/` directory exists yet — not present, both declared downloadables (`offline-html`,
`pdf`) are build-generated. Create `assets/` only if you add a genuinely pre-built file (e.g. a
hand-made PDF).

`manual.json` fields:

| Field | Meaning |
| --- | --- |
| `version` | `MAJOR.MINOR.PATCH`. Becomes the release directory name — readers always get the newest. Releases are immutable: the server caches each version's manifest for the life of the process, so any change (even a `free` flag) ships as a new version. |
| `documentsAppVersion` | Which session-manager release this edition describes. Bump it when the UI moves. |
| `chapters[].free` | Must be `true` on **every** chapter — the manual is free (root `CLAUDE.md`, open-core law). Bilko's chapter route keys its lock on this flag, so the build refuses any chapter that lacks it. |
| `chapters[].part` | Optional string. Chapters sharing a value are grouped under that heading in the table of contents. |
| `assets[]` | Downloadables. `offline-html` and `pdf` are generated by the build (the PDF is rendered from the offline HTML edition via headless chromium); anything else must exist under `assets/`. Write `{version}` in a `file` name (`field-manual-{version}.pdf`) and the build substitutes the release version — a frozen filename hands readers a download that lies about which edition it is. |

## Building a release

```bash
npm run manual:check     # validate sources, write nothing
npm run manual:build     # emit ../Bilko/data/manual/releases/<version>/
```

The build refuses to emit when a chapter file is missing, a slug is malformed or duplicated, an
asset is declared without a source, or any chapter is not marked `free: true`. It wipes and
rewrites the target release directory so a stale chapter from a previous build of the same
version can't ship silently.

## Release checklist

1. Edit chapters here. Keep every claim checkable against real code — readers follow it step by
   step, so a wrong instruction breaks their setup.
2. Bump `version` (and `documentsAppVersion` if the UI changed).
3. `npm run manual:build`.
4. Commit **both** repos: sources here, the emitted bundle in `~/Projects/Bilko/data/manual/`.
   Render serves from the repo, so an unpushed bundle is an unpublished manual.
5. Verify at `/manual`: every chapter renders signed-out with no lock or price, and both
   downloads (offline HTML, PDF) work without a purchase.

## Pricing: free (since 2.0.1, 2026-09-25)

The manual is free — every chapter, the offline HTML edition and the PDF — and nothing is for
sale. Through 2.0.0 it was sold as the `session_manager` one-time purchase
(`STRIPE_PRICE_SESSION_MANAGER`, $19.99). That Stripe wiring stays in Bilko only so a late or
in-flight payment still resolves, and past buyers keep their entitlement rows. It must never gate
a chapter or a download. Server contract lives in `~/Projects/Bilko/server/routes/manual.ts`; the
product constants are in `~/Projects/Bilko/shared/manual-catalog.ts`. See
[`RELEASE-2.0.1.md`](RELEASE-2.0.1.md).

## Figures

A chapter declares a figure slot as:

```html
<figure class="manual-figure" data-figure="scheduler-queue">
  <div class="manual-figure__frame" data-capture="Scheduler tab, Queue view, one running job"></div>
  <figcaption>
    <span class="callout" data-arrow="left">1</span> …
  </figcaption>
</figure>
```

Until a real screenshot lands in `figures/`, the slot carries no image. It never renders a broken
image and never fakes a screenshot, and as of 2026-09-02 it renders **nothing at all** to a reader:
the `.manual-figure:has(.manual-figure__frame){display:none}` rule (in `web/manual/build.mjs`'s
`OFFLINE_CSS` and, mirrored, in Bilko's `src/index.css`) hides the whole figure, caption included,
rather than showing a reader a hatched "figure pending capture" box. The rule goes inert the
moment `npm run manual:figures` swaps the frame for an `<img>` — it is a floor under the product's
finish, not a substitute for capturing the figure.

### Capturing figures

`npm run manual:figures` (script: `web/manual/capture-figures.mjs`) drives the real app under
the same Playwright-Electron + xvfb pattern as `npm run test:e2e`, navigates to each figure's
declared surface, and composites numbered arrow callouts onto a real screenshot with `sharp`.

Every `<figure data-figure="ID">` needs a matching entry in `figure-captures.json` (sibling to this
README) that declares, per figure: the `navKey` to reach it (a `nav:<key>` id from
`CommandPalette.tsx`), any setup `steps` (e.g. clicking into an Epic), a `waitForSelector` that
gates the screenshot, and one DOM `selector` per ordered callout — resolved to a live bounding box
at capture time, never a hardcoded pixel guess. A figure whose recipe is missing, or whose selector
never appears on screen, fails the whole run loudly (naming the figure) and leaves that figure's
existing placeholder/image untouched — it never emits a blank, cropped, or synthesized image.

The script refuses to run if **Session Manager is open at all** (it probes the admin API named in
`~/.claude/session-manager/admin-api.json`), or if any project's scheduler queue has a `running`
job. An idle queue is not sufficient on its own: a second Electron instance rewrites
`admin-api.json` out from under the running app — breaking its scheduler tooling — and any *queued*
job the live instance starts mid-capture becomes a running job that the second instance's boot
reconciliation would SIGTERM. **Quit the app before running this.**

`web/manual/build.mjs` copies `figures/` verbatim into the release bundle, so re-run
`npm run manual:figures` before `npm run manual:build` whenever a captured surface's UI changes.
