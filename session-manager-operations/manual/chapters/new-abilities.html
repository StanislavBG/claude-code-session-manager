New abilities — skills, plugins, tools and hooks

Teach your agents new tricks: packaged skills, plugins, connected tools and automatic hooks — and how to add them safely.

Your agency doesn't stop at whatever Claude Code knows out of the box. You can teach it new know-how, connect it to outside tools, and set up actions that fire on their own. On Home, the Extensions page has a tab each for Skills, MCP Servers, and Plugins. Hooks live in a tab inside Settings, because they're part of the settings file.

Each of these edits a real file Claude Code already reads — nothing here is a parallel system layered on top. A single project can also keep its own skills and MCP servers. You'll find those on that project's Claude config page.

Skills: packaged know-how

A skill is a set of written instructions for one kind of task, saved as a file. Some skills start on their own — Claude notices your request matches what a skill is for, and loads it without you asking. Others only run when you type a slash command, like /develop.

The Skills tab lists what's already on your machine, split into two groups: Skills and Slash Commands. Pick a skill and you can read it, edit its description and body, and press Save to write the change back to its file. You can also turn it off with a Toggle without deleting it — handy if a skill keeps firing when you don't want it to. Removing a skill moves its folder to the trash, so a change of mind later is still recoverable.

Skills and commands that came with a plugin appear in their own From plugins group. You can open and read them, but not edit them here — they belong to the plugin.

To add one, press + New. Choose New skill or New command to name a blank one and write it yourself, or Browse catalog… to open a searchable catalog of skills you can install.

Think of it like this: a skill is a training manual one of your agents keeps on a shelf. Some manuals they reach for automatically, the moment the job looks familiar. Others they only open when you hand them the exact page number.

Plugins: bundles from the catalog

A plugin is a bundle — several skills, agents, or connected tools, packaged together and installed in one step. The Plugins tab lists every plugin already on your machine: its name, where it came from, and a drill-in showing exactly what it added. Each one has a switch to turn it on or off, and a ⋯ menu with Uninstall, which asks you to confirm right there in the menu.

Under each plugin, small chips count what it adds — skills, commands, MCP servers, agents, hooks. A chip marked › switches to the Extensions tab that lists those items (Skills or MCP Servers). A chip marked ↗ takes you to the page that owns that kind: Agents for agents, Settings ▸ Hooks for hooks.

You can look inside a plugin, but you can't edit its contents from here. That keeps one clear place to edit a skill, instead of two competing editors for the same file. To add a new plugin, press + Add plugin. Each row in the catalog shows the plugin's name, a description, and an Install button that runs a real install for you, in the background, with progress shown right in the row.

MCP Servers: connecting outside tools

MCP stands for a protocol Claude Code uses to reach tools that live outside your project — a database, a ticket tracker, another app entirely. The MCP Servers tab lists every server you've registered for your whole machine. A server meant for one project only goes on that project's Claude config page, in its MCP tab. To add one, press + Add server: choose New server to fill it in yourself, or Browse catalog… to pick one from the catalog.

Adding a server to the list only proves the entry is well-formed. It says nothing about whether Claude Code can actually reach it. A misspelled command, a service that needs you to sign in first, or a server still waiting on your approval all look identical on the page: present, and untried.

That's why the tab gives you a live check — and it only runs when you ask, never just because you opened the page. Press Check all to try every server in the list, or Check again on one server's detail to try just that one. A check really connects to the server and asks for its tools. Each server then shows a status dot, the detail shows how long ago it was checked, and its Tools section lists the tools that server offered on the last check. A server nobody has checked yet stays Not checked. Read that status before you start a Session that assumes a server's tools are there — a Session that starts before a server answers won't pick up its tools partway through.

Servers that a plugin brings appear in a From plugins group. You can check them like any other server, but you edit them through the plugin, not here.

Try this: after adding or editing any MCP server, press Check again on it right away. A saved entry and a working connection are two different things, and only the check tells you which one you have.

Hooks: automatic actions on events

A hook is a small command that Claude Code runs by itself, triggered by something happening in a Session — before it uses a tool, after it stops, when a Session begins. The Hooks tab, inside Settings, edits the exact setting Claude Code already reads. On Home it edits your User file; a project's Claude config page has the same tab for its Project and Local files.

Pick an event on the left, then write the command that should run and which situations should trigger it. Saving proves the command is well-formed. It proves nothing about whether the command actually works, whether it matches what you meant it to, or whether it exits cleanly — a typo in a hook can sit there silently doing nothing until the one day you needed it.

That's what the test fire button is for. It sends your command a sample event and shows you the real result — exit code, and everything it printed — before Claude Code ever runs it for real.

Watch out: a hook is a command your machine actually runs, with real permission to touch files or the network. Session Manager always asks you to confirm before test-firing one, naming the exact command first. Only install skills, plugins, MCP servers, and hooks from sources you trust — a hook you didn't write and don't understand is not one to click through blindly, even in a test.

One rule that covers all four

Skills, Plugins, MCP Servers, and Hooks all do the same kind of thing: they give your agents more power than they started with. That power is worth having, but it's also worth checking. Read what a skill actually says before you trust it. Look at what a plugin adds before you install it. Test an MCP server's connection before you build work around it. Test-fire a hook before you let it run unattended.

None of these four tabs invent a system of their own — every one of them edits a real file Claude Code already reads on its next launch. Session Manager gives you a clear way to see what's there, add to it safely, and prove it works before you rely on it.

What you learned

  • Extensions holds Skills, MCP Servers, and Plugins; Hooks is a tab inside Settings.
  • Skills are packaged know-how — some load themselves, some you type as a slash command.
  • Plugins bundle several abilities together; you can switch one off, and + Add plugin is where you install a new one.
  • Test an MCP server's connections, and test-fire a hook, before you trust either one to work.
  • Only install skills, plugins, MCP servers, and hooks from sources you trust — they all run real commands with real permissions.
