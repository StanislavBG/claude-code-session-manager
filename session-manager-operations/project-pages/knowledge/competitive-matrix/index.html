Claude Code Session Manager vs Claude Code Desktop (Claude app), opcode, Vibe Kanban, Conductor

Updated 2026-11-22 · 3 runs · 24 features

Electron desktop cockpit for the Claude Code CLI: per-project tabs, Epics in their own git worktrees, a PRD scheduler for headless claude -p jobs, config/hooks/MCP/plugins editors, local voice dictation, usage history, and a phone remote via bilko.run. Free, MIT, Linux and macOS.

Recommendations

  1. P1Alerts when an agent needs input ◐ PartialStill the clearest open gap. Anthropic closed the Desktop request as not planned (#36885), so a rival weakness stays open. Self already detects needs-input and now renders answerable question cards; only the OS-level and phone push alert is missing.
  2. P2Built-in app preview ◐ PartialSelf shipped Run preview (Nov 12), but Claude Desktop's version closes the loop: the agent loads the page and checks its own change after each edit. That loop is the part users act on. Self's sessions are the real CLI, so the agent can check the page through a browser tool pointed at the preview URL, with no embedded webview (main blocks webview attach).
  3. P2Merge-conflict handling across parallel sessions ◐ PartialCollisions are the main complaint about parallel work and no rival is confirmed to handle them. Self already classifies conflicts at landing; an early overlap warning uses data it already has.
  4. P2Multiple Claude accounts ✗ MissingA loud, long-running request against the market leader that no rival is confirmed to meet. Self launches the CLI itself (node-pty, claude -p), so it can set CLAUDE_CONFIG_DIR per project without touching Claude Code. This fits the TAB = project model. Main risk: the billing usage meter and scheduler limits must read the right account's credentials.
  5. P3Checkpoints and session timeline ◐ PartialSelf already gets CLI /rewind through its real terminal, so the gap is only a visual timeline. opcode (stale releases) and Conductor (title-only) are the only rivals with one; low pull.
  6. P3Multiple agent CLIs ◐ PartialSelf now runs five other CLIs interactively (Nov 13), which puts it ahead of Claude Desktop and opcode. The remaining gap with Vibe Kanban and Conductor is unattended work: a PRD job can only run on Claude Code. That is a deliberate scope line in CLAUDE.md ('others: desktop-only'), so this is low priority unless users ask.
  7. P3Pull request and merge flow ◐ PartialSelf lands locally by design (single-author). Three of four rivals now ship PR flows, Desktop including auto-fix of failing checks, so a PR button matters for team users; still not the owner's core flow.

Feature details

Git worktree isolation per session · Sessions & parallel work

Each session works in its own git worktree and branch so parallel edits never collide, then lands back on the main branch.

Sentiment: complained — Isolation is valued, but users complain each Desktop session leaves a full repo copy on disk with no exit moment: "You close the tab and the session is still in the sidebar, folder and all." HN (Nov 2026): "I ... was happy with it until they made it harder to pick a branch for each worktree!"

Parallel sessions · Sessions & parallel work

Run several Claude Code sessions at once, each on its own task, and switch between them without losing state. Users of this category treat it as the core reason to use a GUI over a single CLI.

Sentiment: mixed — Users want parallel sessions grouped by project ("people want sessions grouped into workspaces by project") and praise the throughput ("feels like the same increase in productivity increase from when I first used Cursor"), but report collisions: "whenever i try to parallelize, they clash while editing files simultaneously" (HN). Desktop users still ask for real multi-window: "this is like browsing the web with just one window and no tabs" (#30154).

Resume and browse earlier sessions · Sessions & parallel work

Find a Claude Code session started earlier — including in the plain terminal CLI — and continue it with its history intact, instead of starting fresh. Users care because long-running context is expensive to rebuild and the CLI has /resume while GUIs often do not see CLI sessions.

Sentiment: requested — Top Desktop request: "Bring session resume to the desktop app at parity with the CLI" (#50067, ~46 thumbs-up); "there's no way to browse or reopen past sessions from the desktop app UI." (#53474).

Task queue / work board · Sessions & parallel work

A board or queue of planned work items that agents pick up, with status that follows the work from planned to merged.

Sentiment: mixed — The board is valued as a planning layer, but HN commenters push back on its access scope: "Why does a kanban board need to see the code or my deploy keys among other things?" Vibe Kanban users value the board itself: "the thing I love about vibe-kanban is specifically the kanban aspect of it" and "the kanban view is DECLARATIVE: you specify a task, the task runs"; they called the Workspaces UI that replaced it "absolutely terrible" (#2288).

Scheduled and unattended runs · Automation & scheduling

Run agent work on a schedule or unattended in the background, with results waiting when the user returns.

Sentiment: complained — Unattended agents stop quietly when they lack input: "the models usually hid the body in the first place because they needed some input they didn't have" (HN). opcode users ask for programmatic launch for automated backlog workflows (#458).

Usage-limit-aware dispatch · Automation & scheduling

Hold queued or scheduled agent work until plan usage has room — fire at the next 5-hour reset or when usage drops below a threshold, and pause on rate limits — so unattended runs do not burn the quota the user needs for interactive work.

Sentiment: complained — Users report parallel and unattended work burning plan limits: "Max 20x effectively equivalent to Max 5x for parallel-workflow users."

Verified completion (gates and validator) · Automation & scheduling

Work does not count as done because the agent says so. Each task carries checks (commands that must pass) that run last, and a second agent re-checks the claims against the real tree before the work is accepted. Users of unattended agents care because a false 'done' costs more to find later than the run saved.

Sentiment: none — No fetched user source discusses verifying agent claims in this category; the user-voice sweep looked for it and found none (noted gap).

Multiple Claude accounts · Agents, tools & configuration

Switch between Claude accounts, such as work and personal, without signing out, or bind a project to one account. Users with separate company and personal plans care because one desktop app forces them to log out or use workarounds like browser profiles or CLAUDE_CONFIG_DIR.

Sentiment: requested — Top desktop request (about 1,000+ reactions per a summarized fetch): "The browser profile workaround shouldn't be the long-term answer when every other productivity tool has solved this already." (#18435). No official response found.

Config, hooks and CLAUDE.md editing · Agents, tools & configuration

Edit every configuration file Claude Code reads — settings scopes, hooks, memory and CLAUDE.md — in the app.

Sentiment: complained — Desktop users report Notification hooks never fire in Desktop Code sessions: "Neither fires in the Desktop-app-hosted session; both fire/work as expected in a terminal session" (#84006, closed not planned). opcode users report "Closing the CLAUDE.md editor tab silently discards unsaved edits".

Checkpoints and session timeline · Code review & landing

Pull request and merge flow · Code review & landing

Sentiment: requested — HN commenters ask for dependent/stacked PRs: "they often need to be dependent on each other - and then I want to make a change to the first one."

Diff review with inline comments · Code review & landing

See what a session changed as a diff, comment on lines, and send the comments back to the agent for another pass.

Sentiment: none

Remote and mobile control · Remote & mobile

Watch and steer running sessions from a phone or another device, including answering approval prompts away from the desk.

Sentiment: requested — Users asked for a phone companion to answer prompts while away: "I am away from the computer (shopping, kitchen, etc.) and Claude Code asks me to confirm or check something." opcode users ask for a web UI. HN users praise Desktop's SSH remotes: "super easy to just add remote machines over ssh".

Usage and cost visibility · Cost & usage

Show plan usage, token spend and cost by session, project and time so parallel work does not silently burn the quota.

Sentiment: complained — Parallel sessions drain plan limits fast ("Max 20x effectively equivalent to Max 5x for parallel-workflow users"), and Desktop users lost per-session cost: "its replacement `/usage` now just opens the Settings → Usage page instead of printing an inline report." They ask for an end-of-session summary (#92109). On caps: "there's zero transparency on what's actually consuming the quota or when resets truly occur" (#9424).

Alerts when an agent needs input · UX & platform

Tell the user — with a system notification or sound, on desktop and phone — the moment a session is blocked on a permission prompt or a question, and let them answer from the alert without losing the question. With several parallel sessions this is how users avoid agents sitting idle.

Sentiment: complained — "When Claude Code requires user approval for a tool call, there is no audio or system-level notification" (#51941). Desktop question alerts break: "For a question, \"Allow\" is not an answer; the quick action destroys the question instead of presenting it." (#89965). Notification hooks do not fire in Desktop (#84006). Desktop: "there's no way to know which session is blocked waiting for user input" (#36885, closed not planned). Vibe Kanban users ask for web push for headless deployments.

Multiple agent CLIs · UX & platform

Drive other coding-agent CLIs (Codex, Gemini CLI, Cursor, OpenCode) from the same app.

Sentiment: mixed — HN users run Claude Code and Codex side by side and call "Claude Code Desktop and Codex (ChatGPT app)" the usability benchmark. Both orchestrators (Vibe Kanban, Conductor) lead with multi-agent support.

Crash recovery and stability · UX & platform

When the app or a window crashes, hangs or is force-quit, it comes back without a reboot and picks up in-flight sessions where they left off. Users running many parallel sessions care because one crash otherwise takes all of them down.

Sentiment: complained — Claude Desktop on Windows failed to relaunch from an orphaned process file lock: "I seriously may have to switch away from Claude as my main workhorse." Marked fixed Oct 23, 2026 ("fixed for me!!"), with some users still sceptical (#42776). opcode users report an infinite spinner on Windows (issues).

Platform support · UX & platform

Which desktop operating systems the app runs on.

Sentiment: mixed — Windows users of Claude Desktop report launch and file-lock failures needing a reboot ("Yes, this is a regression", #42776) while another likes its "Simple UI" (HN). opcode users hit an infinite spinner on Windows and cannot install on Mac (issues).

Voice input · UX & platform

Dictate prompts by speech, ideally on-device.

Sentiment: requested — Desktop users ask for a dictation hotkey: "The voice dictation feature works perfectly via the microphone icon ... but there is no keyboard shortcut to trigger it." (#59400).
