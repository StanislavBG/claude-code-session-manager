### 2. Physical files

Verdict: PASS

### 4. One API per feature

Verdict: FINDINGS (history-F2)

Duplicate-API candidate `history.dashboard` (history, scheduler): **one feature with two call paths**, so it is a finding, not a legitimate second consumer.

- `HistoryDashboard.tsx:123` calls `window.api.history.dashboard({ rangeDays: range })` and holds the result in component state.
- `SchedulerTopBands.tsx:252` calls the same method with `{ rangeDays: 30 }`, wraps it in `withTimeout`, sums the four token fields and `estimatedCostUsd`, and formats them itself.
- Both read the same rollup totals. The scheduler copy re-derives a value (total tokens and cost) that the History view model already computes in `analyticsViewModel.ts`.
- That rule is the charter's: a second page imports the owner's hook or lib and does not call the IPC itself.

### 5. Clear separation and platform adherence

Verdict: FINDINGS (history-F1, history-F4)

- Face law: the page appears on Home only. This matches the `history` entry in `NAV_ITEMS`.
- IPC: `history:dashboard` is zod-validated (`historyDashboard` schema in `src/main/ipcSchemas.cjs:971`) and falls back to `{ rangeDays: 30 }` on a parse failure.
- Errors reach the user through `toast.error`.
- z-index: the only z-class in the owned files is `z-10` on the `ControlBar` sticky header (`ControlBar.tsx:54`). It sits in a local stacking context and is not part of the global ladder.
- Platform: no `process.platform` branches.
- Five owned files import another page's file. See history-F1.
