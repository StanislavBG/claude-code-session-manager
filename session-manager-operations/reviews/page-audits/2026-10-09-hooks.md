Verdict: PASS

`useScopedConfigFiles(SETTINGS_SCOPES, home, cwd)`). Component state is transient UI only (`scope`, `selectedEvent`, `view`, `testFire`
modal, `saveError`). `grep -n "localStorage\|sessionStorage\|process.platform" Hooks.tsx` returns nothing.

### 2. Physical files

Verdict: FINDINGS

The page reads and writes the real `~/.claude/settings.json`, `<cwd>/.claude/settings.json` and `<cwd>/.claude/settings.local.json`, only
the `hooks` key, through `saveJson`. But two edit paths can write content Claude Code will not accept or drop other keys (F1, F2).

### 3. Current, not hardcoded

Verdict: FINDINGS

`HOOK_EVENTS` and `DEFAULT_PAYLOADS` are hand-maintained mirrors and have already drifted from the generated schema (F3, F6).

### 4. One API per feature

Verdict: FINDINGS

`node scripts/page-surface.cjs --duplicates` reports no cross-page duplicate in the page's owned API (`app.testFireHook` is
only used here). One second write path to the same `hooks` key exists in a shared file (F7).

### 5. Clear separation and platform adherence

Verdict: FINDINGS

(a) Electron: the renderer reaches main only through `window.api.app.testFireHook`. The handler validates with
`schemas.appTestFireHook.safeParse`, requires window focus and a native confirm dialog, clamps the timeout to 30 s, and uses
`cleanChildEnv`. No `process.platform` branch, no `zLayers` bypass found.

(b) Claude Code shapes: event names mostly match, but two documented events are missing and three hook-rule shapes do not match
the documented schema (F1, F3, F4, F5). `shell: true` check:

(c) Face law: `navGroups.ts:75` declares `faces: HOME` and the page respects it.
