## Principle checks

### 1. Stateless
Verdict: FINDINGS

Component state is transient UI (`selectedName`, `view`, `filter`, `scope`, `saveError`, `probe`). Server config lives in the `useConfig` store, which projects `~/.claude.json` / `.mcp.json` with a dirty draft. No `localStorage` or `sessionStorage`. Two problems:

- `McpServerEditor` is not keyed by server name, and the name input is `defaultValue={name}`. After selecting another server the input keeps the old name, and its `onBlur` calls `renameServer(selectedName, <old name>)`. That renames the newly selected server to the previous one's name unless that name still exists, so the page can write a name the user did not type. See F1.
- Connection state (`probe`) is fetched on mount and on a button press only. It is never refreshed after a save or an external file change (see F5, principle 3).

### 2. Physical files
Verdict: FINDINGS

The file mapping is right for two scopes. User scope reads and writes `~/.claude.json` `mcpServers`, project scope reads and writes `<cwd>/.mcp.json`, and the write goes `useConfig.saveJson` → `window.api.config.writeJson` → `validatePath` → atomic write. The page offers no scope for Claude Code's third scope. See F2 (missing local scope) and F3 (data-loss path when the file is unparseable).

### 3. Current, not hardcoded
Verdict: FINDINGS

The server list is read through `watchFile` / `config:changed`, so edits made outside the app show up unless the user has a dirty draft. `SERVER_TYPES`, `RESERVED_NAMES` and `CAUTION_NAMES` are small enums of CLI behavior, kept as hand-maintained constants whose comment cites the docs version. Findings: F5 (status never re-probed), F6 (probe runs from the wrong cwd).

### 4. One API per feature
Verdict: FINDINGS

`node scripts/page-surface.cjs --duplicates` reports no duplicated `window.api` method for this page. The page's only own method is `mcp.status`. The shared hooks it uses (`useConfig`, `config.watch`) are the common route. One duplicated code path, not an IPC duplicate: `McpServers.tsx` (`parse`/`serialize`) and `Library.tsx` (`writeInstall` / `uninstall`) each hand-roll the "read `~/.claude.json`, replace `mcpServers`, write" sequence. See F4.

### 5. Clear separation and platform adherence
Verdict: FINDINGS

(a) Electron: renderer reaches disk only via `window.api`; errors go through `toast`; no `process.platform` branches; no z-index literals in the entry. Face law holds (home only). (b) Claude Code schema: the scopes and fields do not match the documented ones. `claude mcp add --help` on CLI 2.1.290 reports `-s, --scope <scope>  Configuration scope (local, user, or project) (default: "local")`; the page covers only two of the three (F2). The editor also writes fields Claude Code does not document (F7). No import of another page's owned file was found.

### 6. Lean tests
Verdict: PASS

Five test files, all `keep` in `tests/quality/summary.json`; none is `bloat` or `merge`. Reading them: `McpServers.test.ts` (26 lines, one pure function) is small but covers a regression and is a micro-file only by size. No source-text assertions seen. Gap rather than bloat: nothing covers the unparseable-file save path (F3) or the name-input staleness (F1), and the `mcpConnectionState` test file covers `ready` but the listing shows no case for `failed` / `needs-auth` / `pending` (see F8).
