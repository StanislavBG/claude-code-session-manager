### 1. Stateless

Verdict: PASS

`npm run lint:renderer-storage` prints `check-renderer-storage: clean`, and a grep for `localStorage|sessionStorage` across the owned files finds nothing. Terminal theme and font persist through `uiSettingsPrefs.ts` into `~/.claude/session-manager/ui-settings-prefs.json`. The session-slot cap is written by `schedule.setSessionSlots` and then re-polled from main (`useSessionSlots.ts:43-47`). The `pending` value in the slot control (`Home.tsx:638`) is transient UI cleared in `.finally`. No component holds disk-backed data without a re-read path. See F1 for the related stale-until-remount behavior, filed under principle 3.

### 2. Physical files

Verdict: PASS

Every value maps to a file Claude Code reads: `~/.claude/projects/*/*.jsonl` (Recent sessions), `settings.json` scopes via `useEffectiveSettingsFor`, `~/.claude/agents/*.md` via `agents.resolveModelInfo`, `~/.claude/.credentials.json` via `billing.fetch`. All access goes renderer → `window.api` → main. The renderer imports no `fs` or `child_process`.

### 3. Current, not hardcoded

Verdict: FINDINGS (F1, F3)

- Settings scopes watch via `useEffectiveSettingsFor` (`useEffectiveSettings.ts:13`, chokidar-backed).
- Recent sessions scan only on mount/`home` change, with no watch or refresh (F1).

### 4. One API per feature

Verdict: FINDINGS (F1, F2)

Judgement of the planner's duplicate candidates:

- `config.listDir` (memory, overview, plugins, skills): the IPC is a generic directory-listing layer and four pages using it is legitimate. The finding is not the IPC but that `Home.tsx:777-781` hand-rolls the same `~/.claude/projects` scan that `useKnownProjects.ts:108-112` already owns and caches (F1).
- `schedule.runNow`: one feature, three call paths. `Home.tsx:579`, `SchedulerPrdsView.tsx:375,548` and `CommandPalette.tsx:120` each call the IPC directly with different error handling (Home toasts, the other two swallow). Finding F2.
- `schedule.setSessionSlots`: CONFIRMED moved onto the shared setter. `Home.tsx:645` and `SchedulerTopBands.tsx:463` both call `setSessionSlots` from `lib/useSessionSlots.ts`, and the only direct `window.api.schedule.setSessionSlots` call is inside that setter (`useSessionSlots.ts:45`). PASS.
- `billing.fetch`, `agents.resolveModelInfo`, `mcp.catalog`: each has a single renderer caller (`state/billing.ts:66`, `effectiveModelInfo.ts:113`, `useMcpAgentTools.ts:28`); `page-surface --duplicates` lists none of them.

### 5. Clear separation and platform adherence

Verdict: PASS

`Home.tsx` imports only from `lib/`, `state/`, `ui/` and its own `./home/` folder (import list at `Home.tsx:24-57`). No owned file imports another page's file. No `process.platform` branches or raw z-index values in the owned files. Face law holds: the page is declared on the Home face only. Errors surface via `toast` (`Home.tsx:580,647`). Usage meters use the shared `usageWindow.ts`. Not run: `npm run lint` (needs `node_modules` in this worktree).
