## Principles

### 1. Stateless

Verdict: FINDINGS

Installed list is read from `~/.claude/plugins/installed_plugins.json` (`Plugins.tsx:110`) and re-read on external
change via `useConfigDirWatch` (`Plugins.tsx:152`). No `localStorage`/`sessionStorage` in owned files
(`grep` on the five owned files: no hits). `rows`, `selected`, `view`, `dismissedSeeders` are projections or
transient UI. Findings are about the reload path, not authority of in-memory state: plugins-F1 (a reload tears
down the drill-in) and plugins-F2 (a corrupt file renders as an empty list).

### 2. Physical files

Verdict: FINDINGS

Every value traces to a real file: `installed_plugins.json`, `<installPath>/.claude-plugin/plugin.json` (legacy
`plugin.json`), `.mcp.json`, `.lsp.json`, `monitors/monitors.json`, `hooks/hooks.json`, `agents/*.md`,
`skills/*/SKILL.md`. The page is read-only and writes nothing. Gap: the manifest's own component declarations
(inline `mcpServers`/`hooks`, custom paths) are not honoured, and `commands/` is never shown — plugins-F4.

### 3. Current, not hardcoded

Verdict: FINDINGS

No domain catalogs in owned files (the only literal map is `SEEDER_LABELS`, keyed by the `SeedStatus` type, and
section names, which are Claude Code's fixed plugin component kinds). Refresh gap: only
`installed_plugins.json` is watched; edits inside an installed plugin's directory are invisible until the drill-in
is reopened — plugins-F3. `CATALOG_PLUGINS` in `src/renderer/data/catalog.ts` is a hand-maintained mirror owned by
the Library page; the Installed view does not use it (`grep catalog Plugins.tsx` → no hits), so no finding here.

### 4. One API per feature

Verdict: FINDINGS

Install has one path: Library's `window.api.plugins.install` (`Library.tsx:992`), the Installed view never
installs. Skill discovery is split across two implementations — plugins-F5. Duplicate-API candidates judged:

- `config.listDir`, `config.readJson`, `config.readText`: generic file-gateway handlers (`config:*` in
  `src/main/config.cjs`), validated by `validatePath`. Each page reads different files through them; this is a
  generic layer used legitimately → PASS. The only real duplication is the SKILL.md walk, which is a
  lib-level duplicate, not an IPC one (plugins-F5).
- `shell.open`: generic launcher; `main/index.cjs` `shell:open` limits `external` to http/https. Plugins uses it
  once (homepage link, `Plugins.tsx:499`), as do ChatTranscriptTurn and others for the same purpose → PASS.
  (`Plugins.tsx` handles `!result.ok` with a toast; `handleChatLinkClick.ts`/`Terminal.tsx` swallow it —
  not Plugins' file.)

### 5. Clear separation and platform adherence

Verdict: FINDINGS

Good: no fs/child_process, no `process.platform`, no z-index literals, all access via `window.api`; imports are
only `ui/`, `lib/`, `state/` and the sibling `./Library` (shared, reported by the tool as shared with 5 other
pages). Face law holds (home only). Findings: errors swallowed (plugins-F2), hardcoded canvas colours
(plugins-F6), serial per-plugin IPC fan-out from the renderer (plugins-F7).

### 6. Lean tests

Verdict: FINDINGS

Two of five attributed tests are `bloat` (zero-unique-coverage). See "Test reduction candidates".
