### 4. One API per feature

Verdict: PASS

All four duplicate candidates are generic layers, not one feature on two paths:

- `config.readJson` (plugins, projects): `projectsPrefs.hydrate` reads its own prefs file. Plugins reads `installed_plugins.json` and plugin manifests. They share no data or feature, so this is a generic JSON-read primitive. PASS. (The real gap is that `hydrate` is never called; see F1.)
- `files.delete` (projects, skills): the tree deletes a user-selected path. Skills deletes a skill directory, and the shared `DocumentMenu` deletes the open document. Each calls the same single main handler `files:delete` for a different feature. PASS.
- `pty.write` (memory, projects): the tree inserts `@<relpath> ` into the active terminal. `MemoryNaturalPanel` sends a memory prompt. The same PTY transport carries two different actions. PASS.
- `shell.open` (plugins, projects): the tree uses `openPath` and `revealPath`. Plugins uses `external`. It is one multiplexed handler (`shell:open`, `as:` discriminator), so it is already one surface. PASS.

The launcher uses the shared `useKnownProjects`, which is the documented owner.

### Moving ProjectsWorkspace off localStorage

`ProjectsWorkspace.tsx` is allowlisted in `scripts/check-renderer-storage.cjs:20`. It uses two keys: `sm.projects.splitPct` and `sm.projects.fileTreeCollapsed`. Both are personal layout preferences, so they belong machine-wide, next to `fileTreeShowHidden`, not per project. The work is:

1. Add `projectsSplitPct?: number` and `projectsFileTreeCollapsed?: boolean` to the `uiSettingsPrefs.ts` type (shared lib, so the PRD's Files must list it).
2. In `ProjectsWorkspace`, replace `loadSplitPct` and `loadCollapsed` with `readUiSettingsPrefs()` in a mount effect. Keep `SPLIT_DEFAULT` and `false` as the pre-hydration values, and clamp the split to 20-60 as now.
3. Write with `writeUiSettingsPrefs(...)` on pointer-up, on reset and on collapse toggle. Drag stays in React state, and the disk write happens only on pointer-up, as today.
4. Delete the `localStorage` calls and the allowlist entry (the ratchet only shrinks). Handle first paint: the panel shows defaults for one tick, then jumps to the saved width, so a short "hydrated" gate or an accepted flash must be chosen.
5. Add one scenario test: set width and collapse, remount, expect restored from the prefs file. Existing browser keys are not migrated, since the project has no backwards-compat shims; users reset once.
6. Run `npm run lint:renderer-storage`.

It is a small change (about 40 lines), with the shared `uiSettingsPrefs.ts` edit as its only out-of-page file.
