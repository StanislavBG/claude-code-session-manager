## Principles

### 1. Stateless
Verdict: PASS

No browser storage in owned files (`grep -n "localStorage\|sessionStorage"` over owned files hits only a stale comment,
Settings.tsx:89, see F5). The scoped editors keep drafts in `useConfig` and write the real files through `SaveBar`. The
Telemetry, Epic isolation and Remote sub-views hold an explicit draft that is only a pre-save buffer. The module-level
singletons (`rawSessionModel.ts` `current`, `uiChromePrefs` store) are disk projections; their missing refresh path is
a principle 3 finding (F1, F2).

### 2. Physical files
Verdict: PASS

Every value maps to a named file (table above). The three scoped editors write exactly the files the CLI reads
(`SETTINGS_SCOPES` in `lib/scopes.ts`). `epic-worktree-config.json` is built with `opsPath(cwd, 'prompt-sessions', ...)`
and written atomically (`src/main/lib/epic/epicWorktreeProjectConfig.cjs:63-80`). App prefs are app-private files by design
and say so on screen ("not part of Claude Code's own settings").

### 3. Current, not hardcoded
Verdict: FINDINGS

Only the three scoped editors watch their files (`useScopedConfigFiles`). Nothing else in the page does:

```
$ grep -n "watch\|onChanged" src/renderer/components/tabs/Settings*.tsx src/renderer/state/uiChromePrefs.ts src/renderer/lib/rawSessionModel.ts src/renderer/lib/useDensity.ts
src/renderer/components/tabs/SettingsRemote.tsx:385:   : 'Paired devices can watch session output ...'
src/renderer/components/tabs/Settings.tsx:105:  // Resolve + load + watch every scope path so the switcher annotations stay live.
```

Sections that read once on mount and never refresh: OTEL and product telemetry, Epic isolation, density, raw-session
model. See F1, F2. `SETTINGS_GROUPS` is a hand-kept key list (F6), mitigated by the "Other" fall-through.

### 4. One API per feature
Verdict: FINDINGS

`node scripts/page-surface.cjs --duplicates` reported nothing for this page's API. One consumer-level duplicate remains:
`promptSessions.getWorktreeDisabled` is called directly from two places with the same optional-chain/fallback wrapper
(F3).

### 5. Clear separation and platform adherence
Verdict: FINDINGS

No cross-page imports of another page's owned file (`grep` for `tabs/Hooks|Permissions|Skills|Mcp` imports in owned
files: none). No `process.platform` branches, no fs access in the renderer, face law holds (Home only). `otel:set-config`
does not go through a zod schema (F7). `JsonEditor.installMonacoSchemas` is imported by `App.tsx` (shell, not a page);
noted, not a finding.

### 6. Lean tests
Verdict: FINDINGS

Three attributed files are `review (smell:mock-only)` and one is `merge`; see candidates below.
