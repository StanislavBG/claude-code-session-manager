### 1. Stateless

Verdict: FINDINGS

Hotkey, device, wizard and turn-detector config persist only to `~/.claude/session-manager/voice.json`, through
main (`voiceSettings.cjs` → `config.writeTextAtomic`, mode 0600, serialized by `writeQueue`; subtrees preserved by
`writeMerged`). The renderer uses `window.api.voice.*` only. No `localStorage`/`sessionStorage` in owned files
(`grep` over the six owned files found none). The TTS toggle is in-memory by design.

The gap is the re-read path: main caches `currentConfig` and nothing watches `voice.json`.

```
$ grep -nE "fs\.watch|chokidar|watch" src/main/voiceHotkey.cjs src/main/voiceSettings.cjs src/main/voiceWizard.cjs
(no output)
src/main/voiceHotkey.cjs:296  ipcMain.handle('voice:get-hotkey-config', async () => {
src/main/voiceHotkey.cjs:297    if (!currentConfig) currentConfig = await voiceSettings.load();
src/main/voiceHotkey.cjs:298    return currentConfig;
```

`voice:hotkey-changed` is sent only from the `voice:set-hotkey` handler (`voiceHotkey.cjs:311`), so a hand-edited
`voice.json` is not picked up until restart. This contradicts the page's stated invariant that
`onHotkeyConfigChanged` refreshes hand edits. See F1.

### 2. Physical files

Verdict: PASS

Every value on the page maps to a real file: hotkey, device preference and mode toggle come from
`~/.claude/session-manager/voice.json`; the microphone list comes from `navigator.mediaDevices` (live hardware, not
a file). `voice.json` is the app's own file, not one Claude Code reads, which is correct for app-owned config.
Writes go through `config.writeTextAtomic`. A legacy path is migrated once (`config.migrateLegacyHomeFile`).
Recording audio is never written to disk.

### 3. Current, not hardcoded

Verdict: FINDINGS

Device lists are enumerated live. The accelerator display is derived from config. The remaining issue is the same
missing file watch as principle 1 (F1). The VAD assets in `src/renderer/public/vad/` are loaded via

domain catalogs are hardcoded in owned files. `formatAccelerator` (`VoiceModal.tsx:71`) is a small label
formatter, not a catalog.

### 5. Clear separation and platform adherence

Verdict: FINDINGS

Checked and fine: no fs/child_process in the renderer; main files are `.cjs`; IPC payloads are zod-validated
(`validated(schemas.voiceSetHotkey…)`, `voiceSetDevicePref`, `voiceSetTurnDetector`; `voice:set-recording` uses
inline `safeParse`); the page has no `z-[…]` literals of its own; errors are logged, not toasted (see F3). The
`voice` case in `screenComponents.tsx:145` renders `<VoiceModal variant="page">`, the same component as the modal.
Privacy invariant holds:

src/renderer/lib/zLayers.ts:76      recording: 'z-[1000]',   (highest rung; toast is z-[900])

`RecordingStatus` renders for `isRecording || externalRecording`. Transcription is on-device: the only
`http(s)` references in `speechRecognition.ts`/`state/voice.ts`/`speechSynthesis.ts`/`ortWasmProbe.ts` are
comments; `baseAssetPath`/`onnxWASMBasePath` resolve to the bundled `vad/` folder, and there is no `fetch(` to a
remote origin.

Findings: `formatAccelerator` branches on `navigator.platform` (F4). Failure to persist the hotkey mode or device
is only logged (`log.warn`), never toasted, and the UI state has already been changed optimistically (F3). The
face law matches: `NAV_ITEMS` declares `voice` with `faces: HOME`.
